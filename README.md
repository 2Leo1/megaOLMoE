# 🚀 megaOLMoE

Форк фреймворка [megablocks](https://github.com/Muennighoff/megablocks/tree/olmoe) (используемого в OLMoE) с фокусом на глубокую переработку механизма маршрутизации (routing) в архитектуре Mixture-of-Experts.

Вместо стандартного линейного роутера мы интегрировали и оптимизировали фреймворк **L2R (Learning-to-Route)**, использующий низкоранговые проекции, SIPS-скоринг (Saturated Inner-Product Scoring) и многоякорные головы экспертов (Multi-Anchor).

---

## 🛠 Что изменилось относительно оригинального OLMoE

Мы форкнули ядро вычислений Megablocks и внедрили модульную систему роутеров. Основные технические изменения сосредоточены в директории `src/megablocks/megablocks/layers/`:

1. **`arguments.py`**
   Добавлены гиперпараметры для настройки новой маршрутизации:
   * `router_type` (`"basic"`, `"L2R"`, `"Latest"`).
   * `moe_latent_size` (размерность сжатия токена, по умолчанию 64).
   * `moe_num_anchors` (количество якорей на одного эксперта).
   * `sips_beta`, `sips_gamma`, `sips_p` (константы для настройки SIPS-скоринга).
   * `moe_router_use_input_rmsnorm` (предварительная нормализация входа в роутер).

2. **`__init__.py`**
   Внедрен `_ROUTER_REGISTRY` для динамического переключения роутеров (классы `LearnedRouter`) без изменения остального кода OLMoE.

3. **`moe.py`**
   Изменен базовый класс `MoE`. Инициализация роутера теперь идет через реестр (`router_cls = _ROUTER_REGISTRY.get(args.router_type)`). Логика параллелизма (ParallelMLP) и подсчета `load_balancing_loss` адаптирована под новые возвращаемые тензоры.

4. **Новые файлы роутеров:**
   * `routerBasick.py` — классический линейный бейзлайн OLMoE (для контроля).
   * `routerL2R.py` — базовая имплементация L2R.
   * `router_latest.py` — наша оптимизированная версия с обучаемыми параметрами `gamma`/`beta` и улучшенной стабильностью косинусного сходства.

## 🧠 Техническая реализация L2R (`router_latest.py`)

Наш основной роутер работает в 3 этапа. Все операции дифференцируемы и написаны с учетом работы в `bfloat16`/`float16`.

* **1. Low-Rank Projection (`self.down_proj`)**
  Сырой токен сжимается: `hidden_size (384) -> moe_latent_size (64)`. Перед этим (опционально) применяется RMSNorm для стабилизации выбросов (`self.input_rmsnorm`).
* **2. Настройка якорей (`self.anchors`)**
  Вместо матрицы `[hidden_size, num_experts]`, веса экспертов представлены тензором `[num_experts, num_anchors, latent_size]`. Каждый эксперт имеет облако векторов-якорей.
* **3. SIPS-скоринг и LogSumExp**
  * Векторы токена ($q$) и якорей ($k$) $L_2$-нормализуются (`q_dir`, `k_dir`).
  * Считается косинусное сходство: `torch.einsum("...r,nar->...na", q_dir, k_dir)`.
  * Длина вектора токена ограничивается константой Липшица через `tanh` (`phi_q`), что защищает от схлопывания углов (Angle Collapse).
  * Логиты якорей агрегируются в единый скор эксперта через `torch.logsumexp(z_raw, dim=-1)`.

## 📊 Стратегия бенчмаркинга (На масштабе ~500M / 2B токенов)

Из-за жесткого лимита вычислительных ресурсов (модель 8 слоев, размерность 384, ~2 миллиарда токенов на обучение), стандартные метрики `accuracy` работают на уровне случайного угадывания и сильно зашумлены. 

Мы выстроили надежную методологию оценки (см. `configs/model_benchmark_tiny_500m.yaml`):

1. **Главный сигнал (Upstream PPL):** Основной упор делается на held-out perplexity на чистом тексте (`wikipedia-heldout`), который **не входил** в `olmoe-router-2b`. Эвалюация идет батчами по 512, пропуская около 2M токенов. Это дает честный, низкодисперсный сигнал качества роутинга.
2. **Непрерывные метрики (Continuous Loss):** Используется `arc_easy_ppl` (ce_loss). Лосс кросс-энтропии на задачах позволяет увидеть разницу в моделях даже тогда, когда `accuracy` стоит на уровне случайности (e.g. 0.25).
3. **Оценка без обрезки датасета:** Все downstream-задачи (SciQ, ARC, HellaSwag, PIQA) считаются на полных датасетах (`subset_num_batches: -1`). На малых выборках возникали артефактные 100% совпадения скоров между разными моделями. Используются только HF-датасеты без сторонних `oe-eval` данных.

## 💻 Установка и запуск

1. Склонируйте репозиторий с сабмодулями:
   ```bash
   git clone --recursive https://github.com/2Leo1/megaOLMoE.git
   cd megaOLMoE
   ```
2. Соберите и запустите Docker-контейнер (рекомендуется):
   ```bash
   bash install.sh
   ./start_env.sh
   ```
3. Пример запуска бенчмарка из скриптов:
   ```bash
   python scripts/model_benchmark.py \
       --run-dir runs/your_model_dir \
       --benchmark-config configs/model_benchmark_tiny_500m.yaml
   ```

## 🛠 Экспериментальные функции в разработке (WIP)

Помимо текущего кода в ветке готовятся следующие математические оптимизации:
* **Геометрическая регуляризация ($L_{anchor}$):** Дополнительный лосс, который "расталкивает" якоря одного эксперта в латентном пространстве, предотвращая их коллапс в одну координату.
* **Progressive Rank Training:** Постепенное "размораживание" измерений `moe_latent_size` от 2 до 64 по косинусному расписанию через мягкие маски (позволяет избежать градиентного хаоса на старте обучения).
* **Entropy-Aware Precision:** Заморозка вычисления энтропии токена через `stop-gradient` для динамического изменения ранга проекции в зависимости от сложности входного токена.
